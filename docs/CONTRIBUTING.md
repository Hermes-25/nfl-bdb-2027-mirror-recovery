# Contributing

Please open an issue describing the scientific or reproducibility problem before proposing a substantial change. Include a minimal example, environment details, and the exact evaluation scope affected.

Preserve the original frozen evaluation and its eight source cells. Label every new method, selection rule, or cohort evaluation explicitly. Fit preprocessing and tune models inside training folds; keep repeated player identities together. Report unsuccessful comparisons and distinguish conditional intervals from refit uncertainty.

Do not upload official competition files, credentials, private player-level diagnostics, or generated run directories. New code or documentation should pass `python scripts/verify_repository.py`; intentional artifact changes also require updating the manifest and documenting provenance. Scientific changes need official-data execution and a separate validation record.
